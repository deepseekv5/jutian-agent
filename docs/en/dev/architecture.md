# Architecture

> [← Back to docs index](../../../README_EN.md#docs)

Jutian Agent is a three-layer architecture, and each layer can be understood on its own:

```
┌──────────────────────────────────────────────────────┐
│                 Electron main process                │
│  ┌──────────────┐   ┌──────────────────────────────┐ │
│  │   serve.cjs  │   │  Window / tray / global      │ │
│  │  (HTTP :3211)│   │  shortcuts                   │ │
│  │  38 built-in │   │  Window-state persistence    │ │
│  │  tools       │   │                              │ │
│  │  llm-proxy   │   └──────────────────────────────┘ │
│  │  MCP client  │   ┌──────────────────────────────┐ │
│  │  Cron jobs   │───│  Phone remote gatekeeper     │ │
│  │  Notify      │   │  (pairing code)              │ │
│  │  bridge      │   └──────────────────────────────┘ │
│  │  diff log    │                                    │
│  └──────────────┘                                    │
└───────────────────────────┬──────────────────────────┘
                            │ HTTP (same host)
              ┌─────────────┴─────────────┐
              ▼                           ▼
      React renderer (:5173 dev)    Phone browser (LAN)
      /api/* relative paths         remote.html single page
```

## Responsibilities of the three layers

### 1. serve.ts — single-process backend (sole source: `src/server/serve.ts`)

- **Tool API**: implementations of the 38 built-in tools, all returning the `{ success, output }` shape
- **llm-proxy**: `/api/llm-proxy` forwards OpenAI-compatible streaming requests; upstream errors are passed through with their status code unchanged
- **MCP client**: stdio JSON-RPC 2.0, manages the external tool ecosystem
- **Gatekeeper chain**: OPTIONS preflight → untrusted Origin gets 403 → DNS rebinding gets 421 → non-local requests go through the pairing code
- **Persistence**: SQLite (`~/.lyclaw/data.db`) via `src/shared/db.cjs`

> The build artifact `serve.cjs` is generated by `npm run build:server` — **do not edit it by hand**.

### 2. Electron main process (`electron/`)

- Window lifecycle, tray, and state memory (window-state persistence)
- In packaged builds, serve.cjs runs directly inside the main process — no separate terminal window needed

### 3. React renderer (`src/renderer/`)

Organized by domain — one directory per feature domain:

```
src/renderer/
├── app/        App shell: TabBar / Sidebar / notification center / LY HARNESS panel
├── chat/       Main chat: composer / message bubbles / thinking level / mode toggles
├── code/       Code mode: file tree / multi-tab editor / terminal / diff
├── agents/     Swarm: employee chats / group chat
├── panels/     Standalone panels: free models / knowledge base / PPT, etc.
├── settings/   Settings: reasoning / remote / language / backup
├── media/      Voice / audio
├── engine/     Streaming engine / sub-agent parallel pool / agent loop
└── hooks/ store/ types/ utils/
```

## Key data flows

**One conversation turn**: the renderer sends `POST /api/llm-proxy` (SSE) → the model returns `tool_calls` → the renderer calls `POST /api/tools/execute` for each one → serve executes them (or forwards to MCP) → results are fed back → loop until the model gives its final answer. Tool schemas come from `src/shared/builtin-tools.json` (the single source of truth shared by all three ends).

**Sub-agents**: the worker pool in engine/subagent.ts (concurrency 3) runs the full tool loop independently for each sub-agent; progress is pushed to the sidebar and the phone client via the `subagent-progress` window event.

## Port conventions

| Port | Purpose |
|---|---|
| 3211 | Backend API + production-mode pages (fixed, do not change; remote access also goes through it) |
| 5173 | Vite dev server (dev only; `/api` is proxied to 3211) |

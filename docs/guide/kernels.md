# 推理内核（四内核对照）

**简体中文**

> [← 返回文档索引](../../README.md#docs)

巨天agent 内置四套推理内核，都跑在同一份 58 工具与安全门禁之上，区别在「怎么把一轮对话跑成一件事」。推荐 **JT Core Super**——它会替你在另外三套之间自动路由（在设置里选一次即可）；想手动控制时再往下看。

## 四内核对照

| 内核 | 定位 | 机制 | 适合场景 |
|---|---|---|---|
| **JT Core Pro+** | 通用默认 | 五阶段工具循环（准备 → 请求 → 流式 → 门禁 → 执行），跑到「无工具调用的最终答复」即交卷 | 日常问答与常规任务 |
| **JT Core Ultra** | 高护栏 | gemini-cli 护栏全量移植：FSM 状态机、循环检测、模型回落 | 步骤多、容易绕圈的复杂流程 |
| **JT Core Auto** | 自主目标闭环 | 独立评估器逐轮判定完成度，未完成自动续跑；三态保护（评估不可用绝不续跑）、停滞检测、轮次封顶 5 轮 | 「做完为止」的端到端任务，如批量改造、多步部署 |
| **JT Core Super** | 最高端（推荐） | 全自动路由：11 阶段流水线把前三套当执行器，连模型也替你选 | 不想研究内核的所有人 |

## 怎么切换

三处入口，效果相同（选择持久化保存）：

1. **设置 → 推理 →「JT Core 内核」**：一排按钮直接点选
2. **输入框下方状态条**：内核按钮点击即循环切换
3. **命令面板**：搜索「切换到 JT Core …」（Super / Auto / Ultra / Pro+）

终端版用 `jt --engine=ultra|auto|super` 指定内核（v18.1.2 起支持），未指定时走服务端默认（见 [终端版](tui.md)）。

## JT Core Super：把选择权收走

Super 内核对每次请求跑一条 **11 阶段流水线**：

```
信号采集 → 复杂度评分 → 任务分析 → 执行计划 → 策略选择
→ 内核路由 → 模型选择 → 上下文工程 → 护栏
→ 执行（Pro+ / Ultra / Auto 三选一）→ 反馈学习
```

- **全自动**：用哪套内核、挑哪个模型、上不上护栏、要不要自主续跑，都由它决定
- **可解释**：每步决策带理由与置信度，完整 trace 进事件总线——诊断面板可查「为什么这样路由」
- **静默**：内部状态不进正文，界面上只看到活被干完；模型不会自我介绍「我用了 Ultra」
- **反馈学习**：按「策略 × 任务领域」统计历史成功率，样本充足才微调路由权重

## 与模型选择的关系

- **Super 档**：模型由流水线自动选（按任务复杂度与领域挑合适的模型），推理设置里填的模型作为基准
- **手动档（Pro+ / Ultra / Auto）**：模型就是你在 **设置 → 推理** 配的那个，详见 [模型接入](models.md) 与 [免费模型](free-models.md)

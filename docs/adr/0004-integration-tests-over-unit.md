# ADR-0004：安全防护用集成测试而非单测

**状态**：已采纳

## 背景

项目从零测试起步，需要为路径穿越、SSRF、跨站门卫等防护建立回归网。
常规做法是把防护逻辑抽成纯函数单测。

## 决策

**`tests/security.test.ts` 走集成测试**：`spawn` 真实的 `serve.cjs`，
用 HTTP 打端点断言响应。

## 理由

1. **测的正是攻击者走的路**。防护的失效点往往不在判定函数本身，而在
   「判定有没有被调用」「中间件顺序对不对」「请求是否先被别处处理了」。
   单测判定函数无法发现「函数写对了但没接上」这类问题。
2. **serve.ts 不适合拆出内部函数**（见 ADR-0001）。它是在 Electron 主进程内
   运行的单文件后端，为测试而拆函数要先动这个 4000 行的文件，
   风险高于收益。
3. **顺带验证服务可启动**。集成测试天然覆盖「改坏了导致服务起不来」——
   这是单测发现不了的。

## 影响

- `tests/security.test.ts` 在 `beforeAll` 里 `spawn` 服务并等待 `/api/health`，
  用随机高位端口避免与开发中的 3211 冲突
- 请求必须带同源 `Origin`，否则会被跨站门卫 403（测试里已封装）
- **前置依赖**：需要先 `npm run build:server`；CI 中 `npm test` 排在
  `build:server` 之后
- 纯判定逻辑仍写单测（更快、更细），两者并存：
  - 集成测试负责「防护接上了吗」
  - 单测负责「判定的边界对吗」（如 `tests/sensitiveOps.test.ts`）

# ADR-0005：工具循环必须有轮次与重复调用护栏

**状态**：已采纳

## 背景

主对话的工具循环是 `while (true)`，原先没有任何上限。模型如果陷入工具循环
（反复调同一工具、或不断发起新调用），会一直执行下去——消耗额度、跑光时间，
用户只能手动点停止。这是与同类工具最明显的一处能力差距。

## 决策

加两道护栏，判据集中在 `src/renderer/engine/toolLoopGuard.ts`：

1. **轮次上限 12 轮**（`MAX_TOOL_ROUNDS`）
2. **重复调用检测**：同一工具 + 完全相同的参数超过 3 次即拦下
   （`MAX_REPEAT_CALLS`）

## 理由

1. **必须有硬上限**。仅靠提示词约束模型「不要重复调用」不可靠，
   同 ADR-0003 的逻辑——边界要落在代码里。
2. **上限值取 12 而非更小**。真实任务常需要多轮：读文件 → 搜索 → 改 →
   跑测试 → 再改。12 轮足以覆盖正常复杂任务，同时能及时打断失控循环。
3. **重复检测比轮次上限更早生效**。空转的典型形态是「同一参数反复调同一工具」，
   这种情况在第 4 次就拦下，不必等到 12 轮耗尽。
4. **前两次放行**。重试是合理的——首次读取可能因文件锁、网络抖动失败。
5. **拦截要给出路**。拦截信息不是「已阻止」，而是「请改用不同参数、
   换一个工具，或直接基于已有结果回答」——模型据此能改方案而不是卡住。

## 影响

- 新增工具时无需改动护栏（按签名自动生效）
- 参数顺序不同视为不同调用：完全相同的串才算空转，参数变了说明模型在尝试
  别的路子，应放行
- 触达轮次上限时向用户如实说明「任务可能过于复杂或模型陷入循环，
  请拆成更小步骤」——不静默中断
- `tests/toolLoopGuard.test.ts` 固化边界值（恰好到上限、恰好第几次重复）
  与防误伤（参数不同不误判、工具名不同各自计数）
